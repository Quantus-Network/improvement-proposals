## Abstract

This document describes a 4-ary Poseidon Merkle tree used to record balance-credit leaves for efficient verification inside ZK circuits ([QIP-0005](./qip-0005.md)). The tree is maintained separately from Substrate's Merkle Patricia Trie; its root (`zk_tree_root`) is published in each block header so proofs can bind leaf inclusion to a canonical chain commitment.

> Note: This Draft supersedes an earlier felt-aligned-MPT design (`Quantus-Network/zk-trie`, vendored as `primitives/trie` / `sp-trie` through tagged releases such as v0.4.4). That path was removed from the chain in [Remove trie db (#514)](https://github.com/Quantus-Network/chain/pull/514) (2026-04-13). The QIP number and Created date are retained; the body now matches the deployed `pallet-zk-tree`.

## Motivation

ZK proof systems are highly opinionated: their native datatype is a [field element](https://rareskills.io/post/finite-fields), not a byte. Substrate's storage proofs are [not ZK-friendly](https://forum.polkadot.network/t/generalized-storage-proofs/1315) — space-efficient encodings produce variable-length fields and complex parsing that inflate circuit constraints.

An earlier design considered felt-aligning the Substrate MPT itself. In practice we instead keep the runtime state trie unchanged and maintain a **dedicated Poseidon Merkle tree** whose leaves and internal nodes are hashed with Poseidon2 in a circuit-native encoding. This gives wormhole spend proofs a simple inclusion argument without paying MPT parsing cost in the circuit.

## Specification

### Tree parameters

- **Arity**: 4 children per internal node
- **Leaf data**: `(to_account, transfer_count, asset_id, amount)`
- **Leaf hash**: Poseidon2 over 8 field elements derived from the leaf encoding
- **Node hash**: Poseidon2 over the four child hashes (compact 8-byte/felt encoding → 16 felts), with children sorted before hashing
- **`MAX_TREE_DEPTH`**: 32 in `pallet-zk-tree` — used primarily to clamp weight metering; inserts use saturating depth growth
- **Circuit `MAX_DEPTH`**: 16 in [`qp-zk-circuits-common`](https://github.com/Quantus-Network/qp-zk-circuits/blob/main/common/src/zk_merkle.rs) — proving cost is paid for a full padded path, so the circuit depth is kept lower than the practical on-chain growth

The on-chain tree is dynamic-depth: a proof emits only `Depth` sibling levels, which the circuit pads up to `MAX_DEPTH`. If the tree ever grows past circuit `MAX_DEPTH`, wormhole proof generation must wait for a circuit + verifier upgrade that raises `MAX_DEPTH`.

Growth tracks **total recorded credit volume**, not privacy-spend volume alone (see "Leaf recording" below). Capacity at depth 16 is `4^16 ≈ 4.29e9` leaves. Per the pallet's own timeline note (`pallets/zk-tree`): at one leaf per block (the mining-reward floor, 12s blocks) depth 16 lasts ~1,600 years; at a sustained 10 transfers/sec chain-wide it lasts ~13 years; even permanently saturated blocks (~50 tps) give ~2.5 years. (Public-input bandwidth bounds in QIP-0005 are not the growth limit — ZK-tree inserts are weight-bound well below that.) `LeafCount` is public storage so exhaustion is observable in advance.

### Header commitment

Each block header includes `zk_tree_root`. Wormhole leaf circuits recompute the Poseidon2 header commitment from:

```text
parent_hash || block_number || state_root || extrinsics_root || zk_tree_root || digest
```

and constrain that commitment to equal the public `block_hash`, while also constraining the Merkle proof's computed root to equal the same `zk_tree_root`.

### Leaf recording

The runtime records a ZK-tree leaf for **essentially every** native balance credit, not only transfers to wormhole addresses. Sources include ordinary Balances events (via a transaction-extension scan), mining rewards, vesting payouts, and genesis endowments.

Documented gaps / special cases (see `runtime/src/transaction_extensions.rs`):

- Root `force_transfer` enacted via the scheduler in `on_initialize` is not scanned and gets no leaf
- Some `force_set_balance` paths likewise get no leaf
- The vesting pallet records pot→beneficiary payouts itself via `record_transfer_proof` in `pay_out` (required so Root-enacted `end_schedule` / `retarget_schedule` via the scheduler still create leaves; the event scan never sees those). The scan skips pot legs so the signed `claim` path is not double-recorded; treasury↔pot legs intentionally get no leaf (keyless pot / signed treasury spend — neither can exit through the wormhole)

Mining rewards call the recorder from `on_finalize` (hook context). Vesting's `pay_out` records inline for all three payout paths — `claim` (signed) and `end_schedule` / `retarget_schedule` (`AdminOrigin`, reachable by Root via the scheduler in `on_initialize`, which the event scan never sees). The scan skips pot legs so the signed path is not double-recorded. Filtering of zero amounts / unsupported assets happens in `record_transfer_proof` — the canonical trait entry that the event scan, mining-rewards, vesting, and reversible-transfers all funnel through. The inner `record_transfer` itself has no such guard and is also reached directly by genesis endowment and exit-credit recording. Neither path checks that the recipient is unspendable. Leaves persist indefinitely, so a later block's tree root can still open inclusion of an earlier credit.

Recipient account bytes are **canonicalized** before hashing (`canonicalize_account_bytes`). The compact 8-byte/felt encoding used for leaves is *non-injective* for limbs ≥ the Goldilocks prime; without canonicalization, two distinct deposits can collide on the same leaf hash and share a nullifier.

## Rationale

A separate tree is simpler and cheaper in-circuit than a felt-aligned MPT:

- Fixed arity and Poseidon hashing match Plonky2's native hash gadget
- Recording all credits (not only wormhole deposits) keeps a uniform inclusion argument and lets mining rewards / ordinary transfers feed the same tree wormhole spends consume
- Canonicalization at write time closes the non-injective compact-encoding collision
- The Substrate state trie remains free to optimize for space without coupling to ZK proving cost
- Publishing `zk_tree_root` in the header gives the verifier a single public commitment that binds leaf inclusion to chain history
