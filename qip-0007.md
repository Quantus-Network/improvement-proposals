## Abstract

This document describes a 4-ary Poseidon Merkle tree used to record wormhole deposit leaves for efficient verification inside ZK circuits ([QIP-0005](./qip-0005.md)). The tree is maintained separately from Substrate's Merkle Patricia Trie; its root (`zk_tree_root`) is published in each block header so proofs can bind deposit inclusion to a canonical chain commitment.

## Motivation

ZK proof systems are highly opinionated: their native datatype is a [field element](https://rareskills.io/post/finite-fields), not a byte. Substrate's storage proofs are [not ZK-friendly](https://forum.polkadot.network/t/generalized-storage-proofs/1315) — space-efficient encodings produce variable-length fields and complex parsing that inflate circuit constraints.

An earlier design considered felt-aligning the Substrate MPT itself. In practice we instead keep the runtime state trie unchanged and maintain a **dedicated Poseidon Merkle tree** whose leaves and internal nodes are hashed with Poseidon2 in a circuit-native encoding. This gives wormhole spend proofs a simple inclusion argument without paying MPT parsing cost in the circuit.

## Specification

### Tree parameters

- **Arity**: 4 children per internal node
- **Leaf data**: `(to_account, transfer_count, asset_id, amount)`
- **Leaf hash**: Poseidon2 over 8 field elements derived from the leaf encoding
- **Node hash**: Poseidon2 over the four child hashes (compact 8-byte/felt encoding → 16 felts), with children sorted before hashing
- **On-chain max depth**: 32 (`MAX_TREE_DEPTH` in `pallet-zk-tree`)
- **Circuit max depth**: 16 (`MAX_DEPTH` in the wormhole circuits) — proving cost is paid for a full padded path, so the circuit depth is kept lower than the on-chain growth cap

> Note: If the on-chain tree ever exceeds circuit `MAX_DEPTH`, wormhole proof generation must wait for a circuit + verifier upgrade that raises `MAX_DEPTH`. At one leaf per 12s block this is centuries away; even at high sustained throughput it is years away and observable via public `LeafCount` storage.

### Header commitment

Each block header includes `zk_tree_root`. Wormhole leaf circuits recompute the Poseidon2 header commitment from:

```text
parent_hash || block_number || state_root || extrinsics_root || zk_tree_root || digest
```

and constrain that commitment to equal the public `block_hash`, while also constraining the Merkle proof's computed root to equal the same `zk_tree_root`.

### Deposit recording

When tokens are sent to a wormhole (unspendable) address, the runtime records a leaf via `record_transfer` into the ZK-tree. Leaves persist indefinitely, so a later block's tree root can still open inclusion of an earlier deposit.

## Reference Implementation

- On-chain tree: [pallets/zk-tree](https://github.com/Quantus-Network/chain/tree/main/pallets/zk-tree)
- Circuit Merkle verification: [qp-zk-circuits](https://github.com/Quantus-Network/qp-zk-circuits) (`wormhole/circuit` ZK Merkle proof fragment)

## Rationale

A separate tree is simpler and cheaper in-circuit than a felt-aligned MPT:

- Fixed arity and Poseidon hashing match Plonky2's native hash gadget
- Leaf encoding is designed around ≤32-bit quantized values so injective felt packing is straightforward
- The Substrate state trie remains free to optimize for space without coupling to ZK proving cost
- Publishing `zk_tree_root` in the header gives the verifier a single public commitment that binds deposit inclusion to chain history
